# 사진 AI 기록 형식 추천 — 설계 문서

- 날짜: 2026-08-31
- 상태: 사용자 승인 완료 (구현 계획 작성 전)
- 목표: 사용자가 사진첩(앨범)에 넣은 여행 사진을 온디바이스 AI가 분석해, 그 사진들로 만들면 좋을 다른 기록 형식(피드·블로그·스트립)을 "사진 묶음 + 형식 + 컨셉 + 프리필"로 추천한다. eOrth의 강점인 다양한 기록 방식을 부각시키는 것이 기획 의도.

## 1. 확정 결정 요약

| 항목 | 결정 |
|---|---|
| 추천 발동 지점 | 사진첩 저장 → 상세 기록카드(TripDetail)에 추천 카드 표시 (본체). 귀국 알림 + FAB 사진첩 강조는 사진첩 생성을 유도하는 부스터 |
| 추천 단위 | 사진 묶음 + 형식 + 컨셉 + 프리필 (탭하면 작성 화면에 사진이 채워진 채 열림) |
| AI 역할 | 사진 판단만. 추천 문구는 AI가 아니라 템플릿 |
| 분석 위치 | 전부 온디바이스. 사진·신호 모두 기기 밖으로 전송하지 않음 |
| 정밀도 전략 | 내장 모델 풀 개방(장면 라벨 전체 수신) + 이미지 지문 + 색감 통계 + 추가 신호(얼굴 클러스터링·OCR·EXIF 심화·POI) |
| 개인화 | 기존 게시물(로컬)로 형식 빈도·무드 분포를 집계해 재순위. 게시물이 있어도 다양한 버전을 함께 제안 |
| 대상 형식 | 1차: 피드·블로그·스트립 3종 (사진첩=발동 전제라 제외, 스냅=즉석 촬영 전용 제외, 모먼트 보류) |
| 분석 시점 | 앨범 저장 직후 저우선 백그라운드. 카드 진입 시 미완료면 자리표시 후 완료 시 교체 |
| 엔진 구조 | 형식별 후보 생성기 + 공통 개인화 재순위 (접근법 A) |
| 평가 | 골든셋 + verify 파일로 일치율 측정 (감이 아닌 숫자로 튜닝) |
| 확장 대비 | 컨셉 판정기를 인터페이스로 분리(2차 CLIP 교체 대비), 사용 로그 스키마 선반영 |
| 범위 제외 | 클라우드 비전 LLM, CLIP 온디바이스 모델 탑재, 원격 구성 튜닝, 모먼트/스냅 추천 — 전부 2차 이후 |

## 2. 전체 구조

기능은 3덩어리로 나뉘며 서로 독립 동작한다.

1. **유도 퍼널** — 귀국 알림 + FAB 사진첩 강조. 위치 권한이 없으면 이 덩어리만 무동작하고 나머지는 정상.
2. **추천 엔진** — 신호 계층 → 컨셉 판정 → 형식별 후보 생성 → 개인화 재순위. 순수 로직은 전부 순수 함수로 분리.
3. **추천 UI** — TripDetail 추천 섹션 + 작성 화면 프리필 라우팅.

데이터 흐름:

```
앨범 저장
  → (백그라운드) photo-vision 확장 분석: 사진별 신호 추출
  → 스팟 그룹핑(기존 photoGrouping) + 유사도 클러스터링(신규)
  → 컨셉 판정기: 사진/그룹에 무드 점수 부여
  → 후보 생성기 3종: (사진 묶음, 형식, 컨셉, 배열, 점수) 후보 산출
  → 개인화 재순위 + 다양성 보장 → 상위 3개 카드 저장(로컬)
  → TripDetail 진입 시 카드 렌더 → 탭 시 작성 화면 프리필 이동
```

## 3. 신호 계층 — photo-vision 모듈 확장

기존 `modules/photo-vision`의 `NativePhotoAnalysis` 반환에 다음을 추가한다. 네이티브는 원시 값만 반환하고 해석·매핑은 전부 JS가 담당한다(파리티 관리 지점을 JS 한 곳으로 고정).

| 신규 필드 | 내용 | iOS | Android |
|---|---|---|---|
| `sceneLabels` | `{label, confidence}[]` 상위 10개 | `VNClassifyImageRequest` (약 1,300 라벨) | ML Kit Image Labeling (약 400 라벨) |
| `featurePrint` | 유사도 계산용 특징 벡터(또는 쌍별 거리 API) | `VNGenerateImageFeaturePrintRequest` | ML Kit 임베딩 대안 또는 지각 해시 폴백 |
| `colorStats` | `{saturation, warmth, contrast, darkness}` 썸네일 색감 통계 | 공용(썸네일 픽셀 통계) | 공용 |
| `faceIds` | 사진 내 얼굴 클러스터 ID 목록(동일 인물 = 동일 ID, 기기 로컬 한정 임의 ID) | Vision 얼굴 특징점 | ML Kit Face Detection |
| `hasText` | 문자 존재 여부(+밀도) — 메뉴판·티켓·표지판 검출 | Vision 텍스트 감지 | ML Kit Text Recognition |

JS 측 추가 신호(네이티브 불필요):

- **EXIF 심화**: 초점거리·조리개(인물/풍경 촬영 의도), 촬영 간격 밀도(연사 구간), 촬영 시각(야간 판정 보강). 기존 MediaLibrary/EXIF 경로 재사용.
- **POI 카테고리**: GPS 역지오코딩을 카페/박물관/해변 수준 카테고리로 내림. 기존 위치 유틸 확장, 오프라인이면 생략 가능(신호는 전부 선택적).

**라벨 매핑 테이블** `src/services/photoAI/labelTaxonomy.ts`: iOS/Android 원시 라벨 → 공통 컨셉 어휘 매핑. 플랫폼 간 추천 차이는 이 파일에서만 발생하도록 격리한다.

## 4. 컨셉(무드) 체계 — 1차 5종

| 컨셉 | 판정 신호(예) |
|---|---|
| 감성 | 미학점수 높음 + 풍경/석양/바다 라벨 + 저채도·따뜻한 톤 |
| 힙 | 야경/네온/도시 라벨 + 고대비 + 어두움 |
| 유쾌·비하인드 | 웃는 얼굴 + 연사 구간 + 미학점수 무관 |
| 미식 | 음식 라벨 밀집 + 메뉴판 텍스트 |
| 기록·정보 | 랜드마크 + 스팟 다양성 높음 + 텍스트 사진 혼재 (블로그 가중) |

컨셉은 형식과 직교한다("피드×감성", "스트립×힙" 등이 카드가 됨).

**판정기 인터페이스**: `ConceptClassifier`(입력: 사진 신호 배열, 출력: 컨셉별 점수)를 인터페이스로 분리한다. 1차 구현은 규칙 기반 `RuleConceptClassifier` 하나지만, 2차에 CLIP 임베딩 기반 판정기로 코드 교체 없이 대체할 수 있는 경계를 지금 만든다.

## 5. 후보 생성기 + 개인화 재순위

각 생성기는 순수 함수. 입력은 (사진 신호 배열, 스팟 그룹, 컨셉 점수), 출력은 후보 `{photos: uri[], viewType, concept, arrangement?, score, reasonKey}`.

- **스트립 생성기**: 스팟 그룹별 베스트컷(기존 `bestCutSelector` 재사용) → 슬롯 수 2~9에 맞는 조합. 유사 연사컷은 featurePrint로 1장만. 얼굴 클러스터 신호로 "동행 투샷 모음" 변형 후보 생성.
- **피드 생성기**: 컨셉별 상위 사진 ≤20장 + 표시 순서. 영수증·스크린샷류(isUtility·텍스트 과밀)는 제외.
- **블로그 생성기**: 스팟들을 시간순 배열, 스팟당 대표 1~3장 → `blogBlocks` 프리필 구조(`image`/`images` 블록 + 스팟 구분)로 변환.
- **개인화 재순위**: 로컬 `recordStore` 기존 기록에서 (a) 형식 사용 빈도 (b) 게시 사진의 무드 분포를 집계해 가중. 기록이 없으면 무가중. **다양성 보장**: 최종 상위 3개 카드는 서로 다른 형식이 되도록 강제(기록이 있어도 여러 버전 노출이라는 요구 반영).
- 추천 카드는 여행(TripGroup)당 최대 3개. 사용자가 카드를 닫으면 해당 후보는 재노출하지 않는다.

## 6. 추천 UI + 프리필 라우팅

- `TripDetailScreen`에 "✨ AI 추천" 섹션. 카드 = 사진 미리보기 썸네일 + 템플릿 문구(i18n 키, `reasonKey`로 선택: "이 4장, 인물 사진이에요 → 스트립으로 만들기") + 닫기 X.
- 분석 미완료 시 "AI가 사진을 보고 있어요…" 자리표시 → 완료 시 교체. 네이티브 모듈 없으면(Expo Go) 섹션 자체 미노출.
- 프리필 라우트 파라미터: `NewRecord`/`BlogRecord`/`CutRecord`에 초기 사진(블로그는 블록 배열, 스트립은 슬롯 배치) 전달 파라미터 추가. 기존 화면 로직 최소 침습 — 파라미터 없으면 기존 동작 그대로.

## 7. 유도 퍼널

- **귀국 알림**: 기존 해외 감지기의 귀국 판정에 얹는다. 문구 예: "여행 사진이 쌓였어요 — 사진첩으로 남겨보세요" → 탭 시 `AlbumCreate` 딥링크. 기존 도착 알림과 이중 발송 금지, 발송 기록 불변식("예약을 취소하는 곳에서 발송 기록도 지운다") 준수.
- **FAB 강조**: 조건 = 귀국 후 7일 이내 && 해당 여행의 사진첩 없음. 표현 = 사진첩 버튼 점 배지 + 미세 펄스. 조건 해제 시 원상복구. 알림·강조는 부스터일 뿐, 추천 본체(카드)는 사진첩만 만들면 권한과 무관하게 동작한다.

## 8. 데이터·저장·성능

- 분석 결과·추천 카드·닫음 기록: 전부 로컬(기존 `photoAIStorage` 확장). 서버 전송 없음 → 동의·개인정보처리방침 개정 불필요.
- 분석: 앨범 저장 직후 저우선 백그라운드, 썸네일 기반. 배터리 세이버 시 지연. 실패한 사진은 건너뛰고 나머지로 진행(부분 결과 허용).
- 무효화: 앨범 사진 추가/삭제 시 해당 여행 추천 무효화 후 재분석. 닫음 기록은 유지.
- **사용 로그 스키마(선반영)**: `{event: 'impression'|'accept'|'dismiss'|'edit_after_accept', cardId, viewType, concept, photoCountSuggested, photoCountUsed?, ts}`를 로컬에 기록. 1차에서는 수집만 하고 소비하지 않는다(2차 개인화 학습·튜닝 재료).

## 9. 평가 — 골든셋

- `src/services/photoAI/goldens/` 에 실제 여행 사진 세트 기반 골든셋(사진 신호 스냅샷 JSON + 사람이 붙인 정답: 기대 형식·컨셉·묶음)을 둔다. 사진 원본이 아니라 **추출된 신호 JSON**을 저장해 저장소 용량·프라이버시 문제를 피한다.
- `feedWindow.verify.ts`류 저장소 규약대로 `formatReco.verify.ts`가 엔진 출력과 골든셋 일치율을 계산·검증한다. 규칙 가중치 튜닝은 이 숫자로 판단한다.

## 10. 검증·파리티 체크리스트

- 순수 로직(그룹핑·컨셉 판정·생성기·재순위)은 전부 `*.verify.ts` 대상.
- 네이티브 확장은 iOS/Android 각각 실기기 검증 필수 항목: 라벨 수신, featurePrint 거리, 얼굴 클러스터, OCR, 100장 분석 소요 시간·배터리.
- Expo Go/네이티브 부재 폴백(null) 경로 확인.
- 알림 이중 발송·FAB 강조 소멸 조건 실기기 확인.

## 11. 명시적 범위 제외 (YAGNI)

- 클라우드 비전 LLM 분석(옵트인 프리미엄으로 추후 검토)
- CLIP 계열 온디바이스 모델 탑재(2차 — 판정기 인터페이스만 준비)
- 규칙 가중치 원격 구성/AB 테스트
- 모먼트·스냅 형식 추천
- 추천 문구의 AI 생성(문구는 영구 템플릿이 아니라 "1차는 템플릿" — AI 문구는 별도 결정 전까지 도입 안 함)
