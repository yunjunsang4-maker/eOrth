# 메이트 추천 활용 선택 동의 — 온보딩 동의 화면 + 재동의 배너

작성일: 2026-08-12

## 배경

`b680d9a`(매칭 프라이버시 하드닝)로 `profiles.mate_reco_optin` 컬럼과 설정 토글을 도입했고,
`0bfe8b7`로 개인정보처리방침에 "메이트 추천에 방문한 나라·도시 이름이 이용된다"는 점과
거부권을 명시했다(2026-08-19 시행). 그러나 **아무에게도 물어본 적이 없다** — 전원
`mate_reco_optin = null`(유예)이고, 거부하려면 설정에 들어가야 한다.

한국 「개인정보 보호법」상 선택 동의 사항은 사전 동의가 원칙이다. 지금은 "명시 + 사후
거부권"까지만 갖춘 상태라, 시행일 전에 실제로 묻는 경로를 만든다.

## 목표

1. 신규 가입자에게 온보딩에서 묻는다.
2. 기존 이용자에게 앱 안에서 다시 묻는다.
3. 서버 변경 없이 클라이언트만으로 끝낸다.

## 비목표

- 거부자에게 기능을 제한하지 않는다. 거부는 '후보로 등장하는 쪽'에만 걸리고, 본인이
  받는 추천은 그대로다(선택 동의 거부를 이유로 기능 제공을 거절하면 제22조 위반).
- 서버 스키마·RPC는 건드리지 않는다. 이미 있다.

## 상태 모델 (기존 그대로)

`profiles.mate_reco_optin` 은 nullable 3-상태다.

| 값 | 뜻 | 추천 후보 포함 |
|---|---|---|
| `null` | 아직 물어보지 않음(유예) | 포함 |
| `true` | 동의 | 포함 |
| `false` | 거부 | **제외** |

⚠️ 서버 판정은 `is false` / `is distinct from false` 로만 쓴다. `= false` 나
`not mate_reco_optin` 은 `null` 에서 참이 되지 않아 유예 중인 기존 이용자가 통째로
추천에서 사라진다.

## 1. 온보딩 동의 화면 (신규 가입자)

### 흐름

동의 화면이 **온보딩의 유일한 Main 진입점**이 된다.

```
BasicInfo (STEP 1/3)
   ↓
TravelImport (STEP 2/3)
   ├── 건너뛰기 ─────────────┐
   └── ImportPhotoSelect ────┤
                             ↓
              MateRecoConsent (Final step)   ← 신설
                             ↓
                           Main
```

현재 Main으로 나가는 `navigation.reset` 은 두 곳이다 — `TravelImportScreen`(건너뛰기
경로)과 `ImportPhotoSelectScreen`(가져오기 완료 경로). 둘 다 동의 화면으로 보낸다.

**단, `fromProfile` 로 진입한 경우는 온보딩이 아니므로 종전대로 `goBack()`** 이다.
프로필에서 '과거 여행 불러오기'를 눌러 들어온 기존 이용자에게 동의 화면을 띄우면 안 된다.

### 화면 내용

온보딩 톤(별 배경 + 유리 버튼)을 따른다.

| 요소 | 내용 |
|---|---|
| 단계 표기 | Final step |
| 제목 | 메이트 추천에 내 여행 기록을 쓸까요? |
| 쓰는 것 | 방문한 **나라·도시 이름** |
| 안 쓰는 것 | 사진·본문·날짜 |
| 끄면 | 내 방문 국가가 다른 이용자의 추천 목록에 나타나지 않음. 내가 받는 추천의 정확도도 함께 낮아짐 |
| 보호 조치 | 같은 곳을 방문한 이용자가 적으면 이름을 표시하지 않음 |
| 체크박스 | **기본 꺼짐** |
| 버튼 | [계속] — 체크 상태 그대로 저장 |

기본값을 꺼짐으로 두는 것은 선택 동의의 사전 동의 원칙에 맞추기 위해서다. 미리 체크해
두면 다크패턴 소지가 있다. 대신 체크하지 않고 넘긴 신규 가입자는 `false`(거부)로 저장되어
추천 후보에서 빠진다 — 의도된 트레이드오프다.

### 저장 실패 처리

`saveMateRecoOptin` 이 실패해도 **온보딩을 막지 않는다.** 실패하면 `null`(유예)로 남고
그대로 Main으로 보낸다. 온보딩 이탈이 더 큰 손실이고, 아래 배너가 안전망이 된다.

## 2. 재동의 배너 (기존 이용자)

### 위치

**소셜 탭 피드 최상단** — 스냅 스토리 라인 위. 추천 카드가 실제로 뜨는 화면이고 방문
빈도가 높다.

### 동작

- **표시 조건**: `mate_reco_optin === null` 일 때만
- **버튼**: [사용 동의] / [사용 안 함] — 누르면 `null` 이 아니게 되어 조건에서 빠지고
  영구히 사라진다
- **닫기(✕)**: 로컬에 시각을 저장하고 숨긴다 → **7일 뒤 재노출**
- 저장 위치: `settingsStore` 에 `mateRecoAskedAt`(ms). 기존 `lastSeenNoticeAt` 패턴을 따른다

배너를 무시하는 이용자는 유예 상태로 남아 추천에 계속 포함된다. 이미 앱 내 공지와
방침으로 고지했고 설정에서 언제든 끌 수 있으므로, 신규 가입자(사전 동의)와 다르게
취급하는 것이 정당화된다.

## 3. 서버 작업

**없다.** `profiles.mate_reco_optin`, `set_mate_reco_optin()`, `fetchMateRecoOptin()`,
`saveMateRecoOptin()` 이 모두 이미 반영·검증돼 있다(2026-08-12 실측: 컬럼 존재,
`k_anon_min()` = 3, 전원 `null`).

## 4. 검증

- `npx tsc --noEmit`
- `node scripts/layout-parity.verify.mjs` — 새 화면이 규칙 1~10을 준수해야 한다
  - 규칙 7: `<Text>`/`<TextInput>` 은 `src/ui/Text` 래퍼에서 import
  - 규칙 10: 버튼 라벨에 `{...andFitText}`
  - 규칙 4: 320dp 초과 고정 폭 금지
- i18n: `ko`/`en` 양쪽 문구 추가
- 수동 확인: 신규 가입 왕복(두 경로 모두), 프로필 진입 시 동의 화면이 뜨지 않을 것,
  배너가 응답 후 사라질 것, 닫은 뒤 7일 전에는 재노출되지 않을 것

## 남은 위험

- 배너를 계속 무시하는 이용자는 유예로 남는다. 강제하려면 모달로 바꿔야 하는데, 이번
  결정은 마찰을 낮추는 쪽이다.
- 신규 가입자 상당수가 거부 상태가 되어 추천 후보 풀이 줄어든다. 추천 품질 저하가
  실측되면 문구를 다듬는 것으로 대응한다(기본 체크로 되돌리지 않는다).
