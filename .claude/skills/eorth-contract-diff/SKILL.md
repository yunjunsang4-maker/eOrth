# 서버↔앱 계약 대조

## 이 스킬이 다루는 것

`_workspace/server-parity/01_server_contract.md`(서버가 제공하는 것)와
`_workspace/server-parity/02_client_contract.md`(앱이 있다고 믿는 것) 두 파일을 받아 대조한다.

두 문서는 서로를 모른 채 각각 만들어졌다. 그래야 한쪽이 다른 쪽에 눈을 맞추며
불일치를 덮는 일이 없다. 이 스킬은 그 독립성이 만든 차이를 읽어내는 단계다.

## 대조 축

각 축마다 "무엇을 비교하는가"와 "어긋나면 언제 터지는가"가 다르다.

| 축 | 비교 대상 | 어긋나면 |
|---|---|---|
| 존재 | 앱이 부르는 테이블/컬럼/RPC가 서버에 있는가 | 런타임에 빈 값 또는 에러 |
| 이름 | `.select()` 문자열의 컬럼명 철자 | **타입 검사를 통과한다.** 조용히 `undefined` |
| 타입 | 서버 컬럼 타입 ↔ 앱 타입 선언 | 숫자를 문자열로 받는 등 비교 실패 |
| 널 허용 | 서버 nullable ↔ 앱의 옵셔널 체이닝 유무 | `?.` 없으면 크래시 |
| RPC 시그니처 | 인자 이름·개수·순서·타입 | 함수를 못 찾거나 잘못된 결과 |
| 반환 shape | `returns` ↔ 앱의 구조분해 | 필드가 없어 `undefined` 전파 |
| 접근 주체 | 본인/타인 데이터를 어느 이름으로 읽는가 | RLS에 막혀 0행 |
| **반영 상태** | `schema.sql에 있음` ↔ `서버에 반영됨` | 코드는 맞는데 서버에 없어 전원 실패 |

## 심각도 분류

발견을 그냥 나열하면 무엇부터 고칠지 알 수 없다. 아래로 분류하라.

**차단(Blocker)** — 지금 배포하면 사용자에게 보이는 고장
- 앱이 쓰는 테이블/컬럼/RPC가 서버에 **반영되지 않음**
- 서버 nullable인데 앱이 옵셔널 체이닝 없이 접근
- RPC 인자 개수/순서 불일치
- 타인 데이터를 본인용 경로로 읽음(RLS 차단)

**위험(Risk)** — 특정 조건에서만 터짐
- 컬럼명 철자 불일치(해당 화면에서만)
- 타입 불일치인데 런타임 강제변환으로 대개 넘어감
- 반환 shape에 없는 필드를 옵셔널로 읽음

**흔적(Drift)** — 지금은 안 터지지만 정리 대상
- 서버에 있으나 앱이 안 쓰는 컬럼
- 앱 타입 선언에만 남은 폐기 필드
- `SERVER-STATE.md`에 기록되지 않은 반영분

## 판정 규칙

**"앱이 틀렸다"고 먼저 단정하지 마라.** 세 가지 경우가 있다:
1. 앱이 앞서감 — 서버 SQL을 아직 안 돌림 → **서버 실행이 답**
2. 서버가 앞서감 — 스키마는 바꿨는데 앱을 안 고침 → **앱 수정이 답**
3. 둘 다 맞고 문서만 뒤처짐 — `SERVER-STATE.md` 갱신이 답

어느 쪽인지는 `SERVER-STATE.md`와 git 이력으로 판단한다. 근거 없이 한쪽을 범인으로
지목하면 멀쩡한 코드를 고치게 된다.

## 이 프로젝트의 알려진 함정

**`public_profiles` 뷰가 `schema.sql`에 두 번 정의된다.** 앞쪽 조기 정의의 컬럼 목록이
최종 정의와 다르면 **재실행이 조용히 실패한다.** "앱은 새 컬럼을 쓰는데 서버에 없다"가
나오면 이걸 먼저 의심하라 — SQL을 다시 돌려도 안 고쳐진다.

**`.select()` 문자열은 타입 검사를 받지 않는다.** 이 축의 불일치는 컴파일러가 절대
잡지 못하므로, 대조에서 놓치면 아무도 못 잡는다. 문자열을 문자 단위로 비교하라.

**1회성 마이그레이션은 재실행하면 안 된다.** `migration-*.sql` 중 일부는 이미 적용됐고
다시 돌리면 데이터가 중복 변환된다. "미반영"으로 판정하기 전에 적용 이력을 확인하라.

## 테스트 시나리오

**정상:** 두 추출 파일이 다 있다 → 8개 축으로 대조 → 차단 2건(서버 미반영 RPC 1,
널 미처리 1) 발견 → 각각 근거 줄번호와 함께 보고.

**에러:** `01_server_contract.md`의 "판독 불가"에 RPC 3개가 들어 있다 → 그 3개는
**통과로 처리하지 않는다.** "대조 불가 — 서버 쪽 판독 실패"로 별도 명시한다.
